# LectureRelay 0.3.1 — Core workflow reliability

**Local candidate; core workflow acceptance completed with remaining quality issues. Not published to GitHub.** The installed app completed a three-minute GUI flow, an independent real 90-minute local speech/translation run, replay/restart checks and controlled failure recovery. Technical terminology, some sentence meanings and audio-discontinuity attribution remain open. [Detailed evidence and limitations](../testing/installed-acceptance-v0.3.1.md).

- Whole-class notes and deep review save section/combine progress, recover bounded output-limit failures, and resume after cancellation/restart. Source/context changes require a new review. Completed results become a new version without replacing manual notes.
- Trash adds **Delete permanently** with typed `DELETE` confirmation. Settings → Data adds **Free all storage…**, requiring `DELETE ALL`, with explicit deletion scope and active-work protection. Preferences, credentials and the installed application remain.
- Fractional timestamps retain their precision. Local transcript provenance and proven historical import metadata are repaired. Notifications were moved above recording controls, and exports no longer automatically open another Explorer window.

The actual prior 90-minute transcript completed: 12/12 sections, cancellation/restart/reuse and one automatic combination-limit recovery. The new independent capture saved 459 bilingual segments; complete-file WAV reading, 234 source-envelope probes, five replay positions and restart persistence passed. Late working-set median was 3,953 MiB, versus 3,949 MiB mid-run; 60 seconds after Stop it was 582 MiB. These desktop results do not establish laptop suitability or classroom factual accuracy. No model replacement or unverified caption-speed claim is included.

The independent observer ran 5,401.703 seconds. Native stop automation required a second click, so the saved file is 5,477.26 seconds including a silent tail; no stop-response benchmark is claimed from that attempt. The combined dropped/discontinuous counter was 17 through the last sparse reading near minute 89, then 186 at final save. Source-envelope checks passed, but the counter does not identify actual lost samples or distinguish driver discontinuities from queue drops. This remains a diagnostic limitation.
