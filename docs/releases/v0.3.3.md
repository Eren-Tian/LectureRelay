# LectureRelay 0.3.3 — Audio continuity and Windows CI

**Windows preview.** [Download the EXE, checksum and build metadata from GitHub Release](https://github.com/Eren-Tian/LectureRelay/releases/tag/v0.3.3). Run the EXE installer; no developer tools or LectureRelay account are required. Local models are downloaded separately in Settings. Upgrading uses the stable current-user install directory and preserves the separate library and preferences.

- Audio capture now reserves a bounded five-second mono-sample buffer, with a separate packet cap. It remains nonblocking and explicitly reports any overflow instead of concealing loss. The previous 64-packet queue held only 640 ms on the tested device and lost 1.29 seconds during real writer stalls.
- Saved event diagnostics distinguish device flags, actual application discards, lifecycle transitions and slow writer operations. Unknown device loss remains unknown, and recording warnings remain visible in replay.
- Automatic Windows checks run frontend types/build, three real React fixtures, ordinary Rust tests, Clippy with denied warnings, formatters and repository checks.
- Cold Windows packaging uses pinned tools and verified native runtimes, without restored project/dependency caches or inference models. It verifies the installed payload, icons and licenses and produces an EXE, checksum and build metadata.

## Validation and limits

The queue-stall regression lost 65,280 samples before the correction and retained all 96,000 samples afterward. Ordinary CI passed 53 application Rust tests plus one environment test; hardware/model tests remain explicitly separate.

Installed acceptance used the hosted installer from product commit `59503ca754ab6c9d1cae3900d28e52b0d3fafd21`. Local speech, local translation and Quiet Mode ran for **90m05.11s**, without continuous injected WebDriver/native IPC polling. All 21,600 regular and 3,440 event-neighborhood source probes matched at a constant offset; no application audio discard was counted. One startup device event remained visible. The saved raw WAV is 91m40.84s including retained lead/tail capture. All 271 bilingual segments, five timestamp playback checks, restart preservation and original-data/preference checks passed.

This release rebuild uses the same product code; later commits change only tests and documentation. Its source SHA, size, checksum and successful cold-build run are recorded on the release page and in `build-metadata.json`. The new binary is not claimed to have separately repeated the 90-minute run or to be byte-for-byte identical to the acceptance candidate.

The probe method has finite resolution and cannot certify every sample or perceptual quality. Exact upstream loss from device flags and the internal cause of slow status emission remain uncertain. Private memory grew approximately 117 MiB during capture, mostly in WebView; both AI workers exited after Stop. Physical unplug, authenticated cloud, fresh-machine WebView2 bootstrap, signing and ordinary-laptop power/noise were not tested. AI translation accuracy remains a separate evaluation.

This remains an unsigned preview. The repository is private, so downloading from GitHub requires repository access. No repository visibility, model selection or existing release asset is changed.
