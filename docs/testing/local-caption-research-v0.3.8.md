# 本地课堂字幕：源码研究与安装版对照 — 0.3.8

## 范围与基线

本轮保留实际 0.3.7 工作树，先提交未推送的历史工作（`7a484c5`），再做小范围修改。没有回退到 GitHub 的 0.3.3。默认仍为本地 Nemotron Streaming EN 0.6B、Hy-MT2-1.8B Q4_K_M；Qwen 课后复习功能保留，本轮不扩展总结质量项目。无云端推理、付费 API 或课堂上传。安装器不含模型权重，使用已有独立下载的模型。

验收在当前 Windows 台式机、安静模式、同一系统声音设备完成，另做真实麦克风采集；窗口只放在竖屏。实际每个 AI worker 的 CPU affinity 为 `[0,2,4,6]`，共同使用这四个逻辑 CPU 索引。整机有 32 个逻辑 CPU。CPU、内存是资源代理，不能证明普通笔记本安静、省电或续航达标。用户在本地日期 2026-10-05 明确要求本轮先不进行 90 分钟测试，因此本报告不提供新版本长时验收结论。

0.3.7 安装版 EXE SHA-256 为 `fff3cb660d67635d3df25420199923b0d9a700234b8ac3685d2a0bf3e7d2a157`。用户数据库和历史验收录音保留；升级校验数据库哈希不变。测试仅通过界面新建带 `[ACCEPTANCE]` 标记的课程和课堂，没有写入或清除其他课堂。

## 确认的延迟与正确性问题

1. **启动与解码不是同一问题。** 旧 90 秒 debug 报告首个中文约 16.23 秒；对应 trace 的首次 `preview_start` 已在首个 speech 事件后约 14.18 秒，后续首 token 约 1.01 秒、完成约 2.20 秒。英文早已出现，等待发生在翻译首次实际执行前。旧 trace 未细分准备阶段，不能进一步断言耗时一定来自文件校验、模型加载或哪个调用。新的安装版基线在修改前已为 7.40 秒，因此不能宣称本轮把 16 秒降到 7 秒。
2. **长句临时翻译停止推进。** 两次假设一致的前缀被限制为 32 词；跨过上限后候选保持相同，直到最终定稿。录音、英文仍前进，中文后半等待。新增回归检查第 32 词之后的推进、替换身份和有界工作量。
3. **入口间隔与句尾条件耦合。** 原 native worker 检查本次 IPC 最后最多 8,000 个采样。缩短入口后一次只有 5,120 个采样，320 ms 停顿也被误判为完整 500 ms 静音。初始候选五分钟出现更多短定稿，不能据此把首次最终译文大幅提前宣称为胜利。最终实现跨批次累计连续低幅采样，满 8,000 才结束；不丢弃低音量音频。C++ 回归验证同一波形按不同批次拆分时状态一致，以及 499.94/500 ms 边界。
4. **实时翻译上下文预算偏大。** 同一个 8,192 token 配置用于短的实时翻译和课后工作。实时设为 4,096，保留课后 8,192，并用当前 worker 的真实 context size 做入场长度校验。提示保留语言、数字、否定、术语与输入边界，去掉冗长重复措辞。
5. **空白输入和测量日志。** 未进入 utterance 时的全零 PCM 不需要开 stream 做编码；只跳过精确数字零，非零低音量和麦克风噪声仍处理，音频时钟继续推进。两个线程的旧 JSON 日志会交织，初始候选发现 40 条坏行；最终写入加锁保证完整行，旧坏行显式排除，不修造时序。

保留预加载、单个可替换临时请求、两个有界最终批次、最终任务优先、会话／原文修订验证、迟到结果拒绝、延期段落明确显示。没有在 live captions 时加载 Qwen，没有用关闭 Quiet Mode 或 GPU 掩盖延迟。

实际改动是本地音频提交间隔从 640 ms 缩到 320 ms，每次仍以两个 160 ms cache-aware 块推进；稳定前缀上限从 32 词／512 字节扩到 80 词／1,024 字节。两次假设一致、保留两个未稳定尾词、至少六词、2.5 秒提议间隔和新增至少四词的限制保留。固定 SDK v0.1.0 的 [C API backend options](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/4f9676226f667d14608487df744f375db87127f8/include/nemo_speech/asr.h) 没有线程设置字段，其 [session 实现](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/4f9676226f667d14608487df744f375db87127f8/src/runtime/ggml/session.cpp) 固定使用四线程。本轮没有把新主线接口误用到旧 SDK，也没有引入 ONNX Runtime 的设置。

## 轻量翻译 B：实际运行的独立实验

从 [Mozilla 当前 registry](https://storage.googleapis.com/moz-fx-translations-data--303e-prod-translations-data/db/models.json) 独立获取 released `en-zh/base-memory` 权重，压缩下载后核对官方未压缩 SHA-256 `4e5accc141373565ddc8fa1565bceaa8d0c3482a82cab8131c719ebcc6c2157c`，模型 43,849,787 字节。没有使用 CourseDude 文件。旧 [Mozilla 模型仓库许可](https://github.com/mozilla/firefox-translations-models/blob/main/LICENSE) 为 MPL-2.0；当前 registry 的具体模型来源、许可和复分发条件若将来打包仍须逐项核验。本轮不分发这些实验权重。

实验 runtime 为 `fxtranslate = 0.5.0`，源码核对 [`f2f77cd`](https://github.com/gregtatum/translations/tree/f2f77cd302bf616367aaf836c034af23dff6266f/inference-rs)，MPL-2.0。读取共享 mmapped 权重，Marian 量化 encoder/SSRU decoder、词表 shortlist、句子切分，网络 feature 未启用。原生开发构建可运行；核对 build 输出发现 MSVC 的 C++ SIMD shim 编译失败，实际退回 portable scalar kernel。因此下面是 scalar 实測，不宣称 SIMD 可用。实验程序不进入安装包，终端用户无需 Python/Conda/CUDA。

同一份五分钟基线的 21 段原始 ASR 文本，加 3 条明确校正的否定／术语／数字检查：载入 13.89 ms（文件缓存已热），翻译中位 277.78 ms，p95 688.76 ms。这是原生离线 translator compute，**不是完整安装版从声音到中文的时间，也不包含与 ASR 的 CPU 争用**。它把 `race condition` 译成“种族状况”；数字和所测否定保留。小样本不足以判定其整体准确率，也不足以默认替代 Hy-MT2。

随后用相同 24 条输入、相同 `[0,2,4,6]` affinity 独立重复两种引擎，Mozilla 实际为 scalar 单线程，Hy 配置四线程。资源范围仅 translator 子进程：

| 引擎                               | 热文件缓存准备 | compute 中位／p95     | 全批 CPU 秒 | 峰值 working set／private bytes |
| ---------------------------------- | -------------- | --------------------- | ----------- | ------------------------------- |
| Mozilla en-zh + fxtranslate        | 13.62 ms       | 256.61／708.39 ms     | 6.94        | 51.77／16.76 MiB                |
| Hy-MT2-1.8B Q4_K_M + CPU llama.cpp | 1,185.67 ms    | 1,337.20／2,144.51 ms | 110.77      | 2,246.74／1,261.81 MiB          |

这证明所测轻量引擎的计算和资源优势，尚未证明接入完整安装版后声音到中文的优势。Mozilla 将专业词汇译错；Hy 在自然课堂也会错，不能据此认定较大模型总是较准。独立实验尚未覆盖与 ASR 同时竞争 CPU、模型安装状态或 end-to-end UI。

因此保留 A，不自动每次同时跑两个翻译器。B 仅验证中文，不扩展为日／韩质量声明。当前 Hy-MT2 的日／韩功能另做安装版运行检查。CourseDude 的清单声明不等于已有可验证的日／韩本地运行器。

当前 Mozilla registry 确实有 en-ja `base-memory/Release`、en-ko `base/ReleaseDesktop`，但 en-ko 的 `base-memory` 标为 `ReleaseAndroid`。这只是资源覆盖核查，日／韩权重没有在 B 中下载执行，不能将 Android 清单当作 Windows 可用性证明。

## 测量定义与证据

`tests/e2e/installed-caption-research.mjs` 控制实际安装 EXE、真实 WebView2、设备采集和界面操作。短比较每约 200 ms 读取原生状态及真实 DOM，完整进程组每 2 秒采样 CPU/working set/private memory。新进程 CPU 从创建时计入，第一观察前已存在的进程不虚构历史用量；0.3.7 初次旧采样器没有 CPU 秒数，重复基线使用新采样器。observer 和 opt-in trace 的开销包含在测量内。

阶段 trace 增加准备开始／完成、ASR partial、稳定前缀资格、排队／执行／首次输出／完成／发布，用来源 ID、范围、revision、SHA-256 匹配；不写实际音频、原文、prompt 或凭据。采样器保留 60 秒检查点。`analyze-caption-research.py` 对同一个 request 配对时间，不相减两个不同分布的中位数。旧 trace 缺少 hash/revision 时只配对其确切来源 ID/范围，并记录损坏行数。

首次英文的自动阈值为四词，中文八字符仅表示首个可见片段，**不等于有意义的翻译**。心理学片段另检查“心理学入门课程”这一相同语义单元出现，避免“关于这些主题的一些”让数字好看。时间先从播放器 `audio-start` 计算，录音包络对齐和声音实际起点的修正另列。短比较的 p95 是有限样本描述，不是性能承诺。

本地证据放在忽略的 `target/latency-study/`：`observation.json`、`stages.jsonl`、`processes.jsonl`、`playback.jsonl`、`analysis.json` 与录音。下载素材、字幕全文、模型和验收库不提交或分发。

首条英文没有改善；中文主题提前约 2.43 秒，完整对比含义仅提前约 0.36 秒。非前缀替换包括原文扩展后重新翻译和转为最终结果，追加字符不计为替换；它是 DOM 观察计数，不是“闪烁感降低”的证据。扩大前缀提高了长句覆盖，也增加修订频率，仍有优化余地。没有采样到译文行消失；不能把 saved 25/25 译文覆盖等同于全部讲话都被识别。

## 准确性、麦克风与保留功能

将完整五分钟转录与官方 OCW VTT 做同一规则的近似 WER：0.3.7 两次心理学样本约 12.59%／12.31%，最终 0.3.8 同素材约 12.86%，算法 holdout 约 8.22%。参考字幕有编辑、cue 边缘不等于逐词时间，口头填充词和数字归一化影响数值；这是比较工具，**不是认证准确率，也没有证据证明新版 ASR 更准确**。

同一心理学五分钟通过 Halo PixelBar 扬声器 → 真实 Yeti GX 麦克风采集，首英文从播放器计时 9.383 秒、首八字符中文 11.125 秒；包络估计修正后约 9.036／10.778 秒，但 acoustic correlation 仅 0.44–0.57，起点修正可信度低。入门课程主题未被识别，近似 WER 32.64%，605 词假设对 723 词参考，有明显漏词。backlog 最大 1.75 秒、保存的 16/16 段有译文、300.28 秒录音可以完整读 PCM 和点击时间戳播放，**这些均不能证明麦克风课堂体验达标**。

麦克风波形显著更弱且混有房间声；没有证据把错误全部归因于 0.004 静音阈值、模型或单个增益设置。本轮未修改系统音量、隐私设置或未经验证的阈值。下一步需要受控自然人声输入、声源距离与信噪比对照；不能用系统音频结果代替麦克风准确性。

原始 ASR 与人工参照官方字幕校正的英文做三组配对独立翻译：

| 内容                    | 原始英文／分段后问题                                                                                | 校正后的观察                                                                            |
| ----------------------- | --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Mark/Laura 主语         | 前一段保留 `If I assert`，后一段只剩从句；Hy 误把知识不足归于 Mark/Laura，Mozilla 也把主语归于 Mark | 补齐同一原句后 Hy 主语恢复；Mozilla 仍把知识不足放到 Mark 身上                          |

500 ms 句尾和 20 秒上限仍可能拆散语义；80 词前缀仍反复翻译已稳定的前半，没有引入真正的提交游标和跨定稿原文上下文。所测中文主题更早出现，不等于所有课堂理解错误已解决。

日语／韩语分别以自然心理学课录制约 90 秒，实际 course targetLanguage、UI、保存和播放检查完成：日语 8/8 段译文、最大 backlog 2.05 秒、队列 2；韩语 7/7、2.23 秒、队列 1。实际有假名／Hangul 输出。日语最终计算最大 6.67 秒、韩语 6.30 秒，部分临时排队达数秒。这里只验功能连接，不能推广中文精测结论或宣称三语言实时质量均达标。

最终版系统声音心理学 320.35 秒、算法 300.31 秒、麦克风 300.28 秒 WAV 全部 PCM 可读，首／四分之一／中间／四分之三／尾端各取十秒作包络对照；系统声音稳定偏移约 0.24 秒，相关约 0.98–0.997。没有人完整听完所有录音，也不是对每个采样点的连续一致性证明。短测结束后录音停止、live 工作结束、回放时长和时间戳点击均检查；字幕窗原生事件／显示／关闭／重开没有停止该次录音。

设置读取失败、下载连接中可取消、失败／ready、笔记草稿竞态、中日韩字幕阅读锚点、原文更新后迟到译文拒绝、停止幂等和资源竞态已有针对性回归，本轮普通检查通过。组件 mock 是回归，不是新用户真实下载或故障的完整 GUI 验收。原有数据、录音、单课堂删除和可恢复复习代码未移除；本轮没有再次在真实课堂库做永久删除、填满磁盘或云端测试。

测试期间经设置界面暂时开启 `liveTranslation`（原为关闭）；其余原始音源偏好仍为麦克风、Quiet Mode 开启、中文、浅色。用户按 Esc 停止界面操作后未再更改设置，已打开的用户应用实例保留。验收课程、录音和模型未删除。
