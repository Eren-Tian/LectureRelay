# LectureRelay v0.2.0 — theme, performance and replay

Date: 2026-10-02. Windows x64. This update replaces the static Appearance and Quiet Mode cards with working global controls. It also improves local input checks and lecture replay after inspecting the supplied Coursedude 0.9.8 installed application. User login was completed manually; no paid cloud requests were run.

## Behavior

- **Appearance:** Light and Dark affect the whole app, captions, replay, dialogs, inputs and native window theme. Click once to apply and save. SQLite is authoritative; a local theme hint styles startup before bootstrap. Existing databases default to Light.
- **Quiet Mode:** on by default; up to four available logical CPUs for local speech. Off restores all CPUs allowed to the app. Both live and post-class workers register with the same native policy. Changes update existing process handles immediately without restarting the model or recording. Save failure retains the previous policy. This controls CPU affinity, not an exact software-thread count, a guaranteed speedup or GPU execution.
- **Independent saving:** these two controls remain available during recording or processing. Updating them does not discard other unsaved settings. Other settings retain their explicit Save changes action and existing recording guards.
- **Input test:** Settings → Audio and Start Lecture offer a five-second test of the selected microphone or system output. A real native level meter reports input or silence/device error. Audio remains in bounded memory and is never saved or uploaded. Recording is blocked until the short test finishes.
- **Replay:** 0.5–2× speed, backward/forward ten seconds, and English/translation search with highlighted matches, result count, clear and empty states. Timestamp playback and editing still use original segment IDs. Search does not filter exports.
- The phoenix remains only beside the app title. Removed slogans stay removed.

## Reference scope

The reference's home, settings and populated lecture replay were inspected through its actual installed WebView. Device testing and explicit playback speed controls informed this update; timestamps, course organization, notes and exports already have LectureRelay equivalents. All code and assets remain original to this repository. This is not full feature parity: reference account/billing/sync, media-file analysis, speaker attribution and generated chapter navigation have not been added in this update. No reference account settings or course data were edited; playback speed was confirmed back at 1.0× after inspection.

- The real native model test was explicitly run and passed: affinity switches, native-rate resampling, partial/final text and worker termination behavior.

- During actual installed recording, worker PID 57628 changed affinity **0xF → 0xFFFFFFFF → 0xF**: **4 → 32 → 4 allowed logical CPUs**, with the same recording ID and increasing recording duration. Software threads were 6/9/9, illustrating why the UI says cores rather than threads.
- Pause/resume/stop, captions, search including regex punctuation, 1.5× playback, ten-second skips and actual timestamp playback passed. Live controls fit at 880×620; normal checks used 1180×780. Original preferences were restored.
- The labelled test recording is 10.91 seconds, with two final segments. All **523,680 mono PCM16 frames at 48 kHz** were readable (1,047,360 bytes). A dropped/discontinuous-buffer warning appeared, so this is not a claim of artifact-free capture.
