# Engineering review — LectureRelay 0.3.2

This review continues the installed [0.3.1 acceptance](installed-acceptance-v0.3.1.md). It covers recording/data integrity, concurrent work, input bounds, provider completion, note editing, visual contrast and Windows packaging. It is a focused engineering review with regression evidence, not an independent security audit or a certification of AI accuracy.

## Findings and corrections

| Area                     | Reproduced or inspected failure                                                                                                                                              | Correction and evidence                                                                                                                                                                         |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Stop and data integrity  | A repeated Stop overwrote a completed lecture's duration with zero and marked it interrupted.                                                                                | Validate the active recorder identity. Return already-saved lectures unchanged; refuse stale IDs during another recording. Regression failed before the fix and passes after it.                |
| Atomic writes            | Concurrent writers shared a `.pending` filename, including destinations with different extensions; bytes could cross destinations. Failed replacements left temporary files. | Unique same-directory temporary files, exclusive creation and cleanup after closing the handle. Eight concurrent writers and failed-replacement regression pass.                                |
| Snapshots and task state | Snapshot reads/writes could finish out of order. Live completion cleared its running flag twice, potentially overwriting a new session's state.                              | Serialize snapshot read/write sequences; finish snapshots before clearing the live flag once. Startup metadata is persisted before capture starts.                                              |
| Imports and PDFs         | A DB failure after committing imported WAV audio could classify the import as an empty failed lecture. PDF size was checked after loading it.                                | Preserve committed imports for recovery. Check metadata before reading and cap the read at 50 MiB plus one byte, including files that grow. Recovery and bounds regressions pass.               |
| Audio warnings           | Queue drops and device discontinuities shared one ambiguous counter; warnings disappeared after recording.                                                                   | Separate dropped buffers, lost mono samples and device events. Persist bounded `recording-quality.json` and show its warning in replay. Diagnostic write failure cannot invalidate a saved WAV. |
| Cloud text               | Truncated or filtered completions could be accepted as final text.                                                                                                           | Require a valid `stop` finish; classify output limits for bounded review recovery. Synthetic provider-response tests only; no authenticated requests.                                           |
| Notes and clicks         | React state alone did not synchronously exclude duplicate actions. Editing during a save could race with persisted notes.                                                    | Synchronous ref guards; lock editing and timestamps while saving; preserve draft on failure and saved notes on discard. Real React component tests with controlled persistence promises pass.   |
| Readability              | Faint secondary text, field boundaries and opacity-based disabled/edit buttons reduced legibility.                                                                           | Stronger light/dark tokens, dedicated control borders, visible selected navigation and readable disabled controls. Selected rendered color pairs pass measured thresholds.                      |
| Packaging                | Version-specific paths drifted; the installer test could repoint daily shortcuts to a disposable directory.                                                                  | Derive installer names from version manifests and verify the stable current-user Programs installation.                                                                                         |

## Verification

- Rust: **50 desktop tests + 1 environment test passed**, 10 opt-in desktop tests and the separately run hardware test are excluded from the default suite. Clippy passes with warnings denied.
- Hardware: actual Windows loopback, idle capture, pause/resume, stale-ID refusal, complete WAV read and microphone capture pass. The short system run saved **6.96 s**, with **0 dropped buffers / 0 dropped samples / 2 device discontinuities**. Those device events do not report how much audio was affected. The test harness emits a missing-icon resource warning; the packaged installer/app/uninstaller icons pass separate verification.
- Frontend: TypeScript, production build, real React save/failure/discard/duplicate-action tests pass.
- Contrast: 23 selected pairs per theme measured in headless Edge after CSS transitions finish. Light auxiliary text is **5.42–6.84:1** across checked surfaces; dark auxiliary text **5.51–9.68:1**. Control borders on input surfaces are **3.85:1 / 4.85:1**. This is not a complete accessibility audit.
- Installer: stable per-user installation, native resource hashes, release EXE payload and canonical icons verified. Installing leaves the database hash unchanged.

The installed short flow passed on the portrait monitor: create a labelled course, switch/save both themes, record actual system audio with Nemotron/Hy-MT2, show English and Chinese captions, pause/resume, Stop, replay a timestamp and reopen the app. The saved WAV contains **66.58 seconds / 3,195,840 mono samples at 48 kHz**, with all declared frames readable, and **7 local/local translated segments**. Recorder shutdown was observed 49 ms after the WebDriver click; this single sample is not a general latency benchmark or a measure of translation-drain time. Both native quality fields and the visible replay warning survived restart. The run again reported **0 queue drops, 0 lost samples counted by the queue, and 2 device discontinuities**.

All original database rows compared unchanged: **5 courses, 32 lectures, 1,520 transcript segments**, plus notes, versions, tasks, glossary and preferences. SHA-256 matches for **34 original recording/model files**; SQLite quick check passed and foreign-key errors were zero. The newly created test course is retained and original Trash classifications are unchanged.

## Dependency review

The production pnpm audit returned no advisories. For Rust, a public RustSec database snapshot at `ef6173cbc5c50ec8166f9a5b28f07834144373ee` was downloaded and compared locally using Cargo semver. The check covered 483 registry package versions and 79 matching advisory records. `glib 0.18.5` (RUSTSEC-2024-0429, unsoundness) and `proc-macro-error 1.0.4` (RUSTSEC-2024-0370, unmaintained) remain in the lockfile for other targets, but neither appears in the Windows x64 normal/build dependency tree. This does not audit bundled native binaries or unknown vulnerabilities.

Automatic approval rejected sending the Rust dependency inventory to OSV because it could disclose the project's stack. The replacement downloaded public announcements only; the project inventory stayed on this PC. No API keys or credential-store contents were inspected.

## Limits and remaining work

The existing 90-minute real-time run belongs to 0.3.1 and is reused as historical evidence, not relabelled as a fresh 0.3.2 soak. The old aggregate counter of 186 cannot be retrospectively split; new diagnostics improve attribution, not audio fidelity by themselves. Another long run is needed to characterize those device events.

Terminology/negation errors and unsupported study-model claims remain documented. This change does not replace models or establish classroom accuracy. Authenticated cloud behavior, physical unplugging, full-disk behavior on a disposable volume, ordinary-laptop power/fan behavior, fresh Windows/WebView2 setup and signing remain outside this round. Original content is preserved; new labelled acceptance content remains available for inspection.
