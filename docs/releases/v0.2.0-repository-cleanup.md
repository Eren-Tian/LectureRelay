# v0.2.0 repository cleanup

This engineering pass keeps the application at **0.2.0**. It changes source organization, generated build locations and the audited runtime packaging set. User runtime paths, schema semantics, recording timing, speech policy and provider behavior are preserved.

## Problems found

The native crate had a flat responsibility map; SQLite initialization/queries/recovery/snapshots shared one file. Frontend serialized types included routing and localized formatting, a workspace file included general hooks/views, and settings/replay pages embedded unrelated feature panels. Production worker builds depended on the experiment cache and copied every SDK DLL. Documentation links followed the former flat docs layout; branding had no documented canonical source. `packages/` only reserved hypothetical future packages.

Inventory ran before moves: 128 versionable source inputs, import/module/build references, manifests, native DLL imports and generated data locations. The repository has no commits: all source was untracked, so there was no file history for `git mv` to preserve. Moves used validated workspace paths and updated references; no Git history was rewritten.

## Moved

- Frontend shell/context/routes to `app`, contracts to `types`, formatting to `lib`, async helpers to `hooks`, styles to `styles`. Live/history/transcript UI now has distinct feature homes.
- Native startup/jobs/assistance to `app`; capture/recording/WAV to `audio`; learning contracts to `domain.rs`; local worker/batch/streaming to `speech`; credentials/endpoint policy to `security`; model manager to `models`; paths/snapshots/recovery to `storage`.
- SQLite initialization and repositories to `database`, with explicit immutable `migrations/001_initial.sql` and `002_classroom.sql`. The schema 1→2 transaction/version gate remains unchanged.
- Production C++ worker to `native/speech-worker/src/main.cpp`. Production SDK/build output to ignored `target/native/speech-worker`; packaged runtime remains Tauri `resources/local-asr` and installed `local-asr`.
- Native build scripts to `scripts/build`; long soak to `tests/soak/local-stt.py` with migration/root references updated. Opt-in internal tests to `src-tauri/src/tests/acceptance.rs`; hardware integration stays in idiomatic Cargo `tests`.
- Architecture/provider/local-speech docs into their named hierarchies; canonical phoenix into `assets/branding/phoenix`.

## Removed

- Unused `packages/README.md`, its empty reservation and workspace glob; unused Cargo workspace alias. No application dependency version changes.
- Nine unused staged SDK DLLs (NMT/TTS/llama and extra redistributables); production now uses the audited nine-DLL ASR import closure. SDK caches and historical binaries remain intact. Stale nested duplicate license copies are removed only from the validated generated staging folder before copying the complete original notice tree.
- Empty former source directories. Generated public SVG is ignored and rebuilt from the canonical source. No recordings, models, historical benchmark evidence or prior release installer was deleted.
- Four disposable codemods used during this pass were removed from ignored `target/repository-cleanup` after completion; the inventory/hash/installer audit evidence remains.

## Consolidated

Model management, Trash, glossary, notes, Q&A and provider-key UI have explicit feature components while retaining the owning page's action/state coordination. Shared Markdown/loading UI moved to shared components. Cloud contracts, official compatible adapter and safe HTTP handling are separate; OpenAI/Groq still share one HTTP setup. Lecture row mapping is shared by queries/recovery. Root SECURITY points to one detailed security overview.

## Preserved

Windows Known Folder/Credential Manager targets, schema SQL, English UI, course/context/glossary, recording/recovery, live and post-class speech, translation queue, model lifecycle, replay/corrections/notes/Q&A/exports, Trash, current-user English NSIS, phoenix platform icons and complete third-party notices. Original SVG, migration SQL, release/benchmark reports and icons are compared with the pre-move inventory.

Historical experiment outputs (including failed Moonshine sessions and the completed 90-minute result) remain evidence rather than being relabelled as new acceptance. Large SDK/weights/audio/generated data stay ignored. See [repository map](../architecture/repository-structure.md), [binary provenance](../licenses/native-runtime.md), [test tiers](../testing/validation.md) and [branding](../../assets/branding/phoenix/README.md).

## Security and dependencies

The source audit checks key/token/private-key/credentialed-URL patterns and ignored local environment files without printing matched values. It found zero potential secrets, cycles, broken document links or unresolved frontend imports. No source EXE/DLL/model/private audio was found. Source binary inputs are only documented platform icons and the NVIDIA license PDF. All application dependencies have code/build references; versions and lockfile resolutions stay pinned. No rotation or history rewrite was needed. This is a pattern-based hygiene scan, not an independent security audit.

## Risks

The recording writer and streaming coordinator remain substantial cohesive modules to preserve tested timing/concurrency. The broad command module retains its shared concurrency gate rather than introducing duplicated gates. No runtime-data migration is part of this task. No new ADR is needed for these responsibility-preserving moves.

Remaining debt: complete GUI and authenticated cloud acceptance, smaller-laptop measurements, project-wide source license/signing/private security contact, and the incomplete original Moonshine stream prototype rebuild recipe. This cleanup does not establish those missing claims.
